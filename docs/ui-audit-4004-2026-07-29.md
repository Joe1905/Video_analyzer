# 4004 全站 UI 审计

审计日期：2026-07-29  
审计地址：`http://192.168.1.254:4004`  
视口：桌面端 `1280 × 800`、移动端 `390 × 844`

## 审计边界

- 覆盖真实页面：主页、Amazon、FastMoss、邻聊、日报、视频播放器、视频分析、Shop、图片工具、视频数据、Proxy。
- 覆盖安全交互状态：导航展开、工具选择、邻聊账户选择、日报话题设置、Proxy 新增代理、Proxy 新增账号。
- 未触发消息发送、视频分析、抓取、下载、发布、登录、保存、删除等真实业务操作。
- 4004 当前数据仅用于读取。审计未复制新的正式版敏感数据。

## 总体结论

当前问题不是单页 CSS 偏差，而是共享视觉层与各页面原始模板叠加后形成的系统性失控：

1. 多数页面对比度过低，正文、边框、按钮和空状态都像处于禁用状态。
2. 页面比例不统一：有的主区极度空旷，有的表单被压在窄栏，有的页面长度达到一万像素以上。
3. 桌面端与移动端采用了不同的临时覆盖策略，导致结构、标题、导航和控件行为不一致。
4. 测试数据链路不完整，真实接口错误直接污染 UI，播放器、飞书账户等关键状态无法稳定复现。
5. 动效集中在整页淡入和按钮 Hover，缺少列表展开、抽屉、内容切换、状态反馈等业务动效。
6. 多处中文发生异常逐字换行、标题粘连和技术字段裸露。

## P0：阻塞验收的问题

### P0-01 测试数据和业务接口没有隔离

- 主页聊天记录直接展示连接字符串和 DeepSeek DNS 异常堆栈，不适合作为视觉验收数据。
- Amazon、FastMoss 缺少稳定的两条完整对话样例。
- 日报头部显示“10 条”，但 `/api/report?raw=1&date=2026-07-29` 返回的视频列表为空，播放器只能进入“未找到视频”状态。
- 邻聊账户选择和 Proxy 新增账号弹窗在首轮审查时停在读取状态；后端对齐后已消除持续加载，见“第二轮复查”。
- 结果：相同页面每次刷新可能出现不同状态，设计无法稳定对照。

整改状态（2026-07-29）：已完成后端对齐。邻聊和 Proxy 现在共用规范化飞书目录，首次同步约 0.7 秒，后续缓存读取约 8–15ms；上游短暂不可用时只读界面会回退到本地已同步目录，账号绑定写入仍强制校验实时白名单。

建议新增显式 `UI_TEST_MODE=1`：

- 所有 GET 接口返回脱敏、确定性的本地 fixture。
- 所有 POST、PUT、PATCH、DELETE 默认返回模拟成功/失败状态，不启动分析、抓取、下载、发布、登录或删除。
- SSE 使用固定时序返回 `queued → running → complete`，另提供可切换的 error fixture。
- 测试数据只保留展示字段，不复制正式代理 URI、登录会话、Cookie、密钥和个人信息。
- 页面必须能通过 query 或测试面板切换默认、加载、空、成功、错误状态。

### P0-02 Proxy 表格横向溢出

- 桌面端账号表格右边界达到约 `1389px`，超出 `1280px` 视口。
- 移动端表格固定宽约 `680px`，右边界达到约 `721px`，只能依赖横向滚动。
- 操作列与飞书用户列被推出首屏，用户会误以为账号不存在。
- 新增代理状态下，左中右三栏同时存在，信息密度与页面宽度不匹配。

### P0-03 移动端 AI 对话头部结构损坏

- 顶部出现尺寸异常且被裁切的对话气泡图形。
- 标题出现“首页AI 对话”“AmazonAI 对话”“FastMossAI 对话”粘连。
- 快捷入口退化为一行文字链接，缺少卡片、图标和足够点击区域。
- 底部输入区按钮拥挤，发送按钮高度不足，图标按钮宽度小于 44px。
- 主页历史消息中的错误长文本占据主要视野，缺少可读的错误卡片。

### P0-04 日报页面长度和首屏比例失控

- 桌面端文档高度约 `7812px`。
- 移动端文档高度约 `12043px`。
- 桌面首屏存在大面积空卡片和固定侧栏，正文内容需要长距离滚动。
- 移动端把完整长报告直接纵向堆叠，没有目录、折叠、分段导航或摘要层级。
- “爆款视频”区域显示 0 条，与头部“10 条”数据矛盾。

### P0-05 邻聊关键入口与移动端账户切换异常

- 桌面端加载门禁已由后端对齐解决，首次目录同步约 0.7 秒，后续缓存读取约 8–15ms。
- 移动端打开“频道”面板后点击“切换账户”没有出现选择弹窗，用户无法从移动端切换身份。
- 移动端虽能看到会话，但顶部只显示“公共频道”，缺少完整产品身份。
- 底部导航文字被视口底部裁切。
- 输入框、添加按钮、发送按钮均存在尺寸偏小或低对比度问题。

后端加载阻断已修复；移动端入口行为及其余 UI 问题仍待处理。

## P1：严重的视觉与一致性问题

### P1-01 全站对比度过低

- 大量正文、边框、按钮、输入提示和空状态使用接近背景色的灰色。
- 蓝色主按钮被降低到近似禁用态，页面缺少明确的视觉焦点。
- 卡片边界和页面背景无法形成有效层级。
- 灰白底、浅灰字、浅蓝按钮在所有页面重复出现，视觉显得发虚。

### P1-02 页面比例不统一

- 视频分析：左侧控件集中在约三分之一宽度，右侧大面积空白。
- Shop：表单、结果、日志三栏宽度不平衡。
- 视频数据：结果与日志占据巨大空白，但表单栏过窄。
- 图片工具：采用独立的大标题营销页结构，与其他工作台页面不属于同一体系。
- Proxy：三栏工作区和宽表格同时存在，桌面端也无法完整展示。

### P1-03 导航展开过程存在文本裁切

- 导航宽度动画和文字显隐不是同一时序，展开中会短暂只显示首字。
- 页面主体虽改变外边距，但不同页面使用不同壳层，移动方式不一致。
- 展开态与收起态的 Header、侧栏、主内容没有统一的单一布局变量。

### P1-04 异常换行、截断与文字粘连

- Proxy 的“休眠中”等状态徽标容器过窄，中文会逐字换行。
- “UI 演示代理”等短文本在窄表格列中异常拆行。
- 移动端 AI 对话产品名和“AI 对话”没有间距。
- 工具弹窗混用中文、英文路径和内部函数 ID。
- 多个图标按钮只依赖 Tooltip 表达含义，但点击区不足 44px。

统一修复要求：

- 状态徽标设置 `white-space: nowrap`，宽度由内容决定，不固定为窄列。
- 标题和产品副标题使用明确的 Flex/Grid 间距，不依赖伪元素拼接。
- 长标识符允许省略或专门换行；中文短标签禁止逐字断行。
- 表格在移动端改为卡片或行详情，不保留 680px 固定表格。

### P1-05 弹窗尺寸与内容不匹配

- 工具选择弹窗可视正文高约 `527px`，内部内容高约 `6683px`。
- 工具树有 19 个分组、约 40 个选中工具，技术描述直接铺满主视图。
- 日报话题设置只有少量内容，但桌面弹窗约 `965 × 731px`；移动端约 `344 × 749px`。
- 日报弹窗桌面、移动端均存在轻微内部横向溢出。
- Proxy 新增账号弹窗已能加载飞书目录，但仍缺少显式的同步中、离线缓存、错误和测试状态。

### P1-06 控件尺寸不满足触控要求

典型问题：

- AI 对话：24px 展开按钮、36px 工具按钮、38–42px 发送按钮。
- 邻聊：34–38px 图标按钮和输入框。
- 视频播放器：24–30px 播放、上一条、下一条按钮。
- Proxy：36px 操作按钮，且一行排列多个高风险操作。
- 多个文本链接只有 18–20px 高。

## 第二轮复查：后端对齐后的真实状态

复查范围：邻聊账户目录、Proxy 飞书目录、Proxy 状态徽标、工具弹窗、工具列表展开/收起，以及上述界面的移动端状态。仍未执行登录、发送、保存、发布、删除等业务操作。

### 已确认解决

- 邻聊“切换账户”桌面弹窗可稳定显示 8 个飞书用户及头像，不再停留在“正在读取账户…”。
- Proxy“新增账号”桌面和移动弹窗均可稳定显示同一组 8 个飞书用户，不再停留在“正在读取飞书用户…”。
- 两处目录的用户数量与顺序一致，说明共享后端目录已经对齐。

### 邻聊账户弹窗仍存在的问题

- 桌面弹窗约 `512 × 670px`，高度占 `800px` 视口约 84%；内容高度已经比可视区多约 `8px`，用户数量继续增加时会迅速变成长滚动弹窗。
- 桌面状态下仍有 6 个可见按钮小于 `44 × 44px`。
- 移动端必须先打开“频道”面板才能接触到账户入口；实际点击“切换账户”后弹窗没有出现，属于功能入口失效，而非加载问题。
- 移动端底部导航固定在 `y=792`、高度约 `52px`，正好贴住 `844px` 视口底部，仍缺少安全区余量。

### Proxy 账号弹窗与表格仍存在的问题

- 桌面“新增账号”内容卡约 `620 × 497px`，飞书目录可以读取；没有未绑定代理时，弹窗只在底部显示说明，主“登录”按钮仍保留，状态表达不够明确。
- 移动端内容卡约 `349 × 509px`，能够显示 8 个飞书用户，但底层页面仍高约 `1286px`，打开弹窗时保留原页面滚动位置，遮罩后的背景会停在任意纵向位置。
- 移动端账号表格仍固定为 `680px` 宽，外层只有约 `317px` 可视宽度，实际横向内容约 `704px`。
- “休眠中”徽标实测只有约 `44 × 40px`，`white-space: normal`，位于约 `60px` 宽的状态单元格内，因此四个汉字被强制换成两行。这是明确的异常换行，不是设计上的两行状态。
- 表头排序按钮高度约 `18px`；刷新、导出及账号操作图标多为 `36 × 36px`，均未达到触控要求。

### 工具弹窗与列表动效仍存在的问题

- 桌面工具弹窗约 `640 × 656px`，正文可视高约 `527px`，但内部滚动高度约 `6683px`。
- 移动端工具弹窗约 `350 × 743px`，正文可视高约 `612px`，内部滚动高度进一步达到约 `8565px`，且弹窗内约 20 个按钮小于 `44 × 44px`。
- 工具树共有 19 个分组。折叠状态虽然配置了 `grid-template-rows 180ms` 和 `opacity 150ms`，但子内容仍保留完整布局高度；代表性分组折叠后高度仍约 `2208px`。
- 实测点击分组切换后，节点会增加 `collapsed` 类，但 220ms 后子内容仍为完整高度，部分节点透明度仍为 `1`。所以当前不是“动效较弱”，而是折叠布局与动效均失效。
- 技术工具 ID 和长英文说明仍直接展示，造成中英混杂、文本密度过高，并放大了无意义滚动。

## 动效审计

现有：

- Header 约 260ms 淡入。
- 主体约 400ms 淡入并上移。
- 导航宽度约 180ms。
- 按钮 Hover 约 140ms。
- 工具树配置了约 150–180ms 的高度/透明度过渡。
- 已存在 `prefers-reduced-motion` 降级。

缺失或失效：

- 工具弹窗使用 `.modal-overlay + .modal-box`，不匹配当前 `.modal.show .dialog` 动画选择器。
- 工具树折叠只改变类名或透明度，内容布局高度没有收起，150–180ms 后仍占据数千像素空间。
- Proxy 新增代理面板、账号弹窗和详情切换缺少一致的进入/退出动效。
- 日报长内容没有分段渐显或折叠过渡。
- 数据加载完成后没有骨架屏到内容的过渡。
- 导航文字在宽度动画开始时立即出现，导致中间帧裁切。
- 移动端抽屉、底部导航和输入区状态缺少统一时序。

## 建议实施顺序

1. 建立 4004 专用测试返回层，固定所有页面数据与状态。
2. 删除当前共享 CSS 中相互覆盖的 V1/V2/“设计稿回归”多层规则，重建单一壳层变量。
3. 先修公共导航、Header、排版、对比度、控件尺寸和移动安全区。
4. 修复 AI 对话三站与邻聊，优先解决移动端。
5. 修复日报和播放器的数据映射、信息架构和长页面。
6. 修复 Proxy 响应式结构、状态徽标和账号弹窗。
7. 修复视频分析、Shop、图片工具、视频数据。
8. 最后统一弹窗、空/加载/成功/错误状态及动效。

## 验收门槛

- 桌面 `1280 × 800` 与移动 `390 × 844` 无页面级横向溢出。
- 所有主要点击区域至少 `44 × 44px`。
- 中文短标签不逐字换行，产品名与副标题不粘连。
- 每个页面可稳定切换默认、加载、空、成功、错误状态。
- UI 审计环境不会调用真实分析、抓取、发布、登录或删除。
- 弹窗尺寸由内容决定，内部不出现无意义的数千像素滚动。
- 导航、弹窗、抽屉、列表展开具有完整进入和退出动效。
- `prefers-reduced-motion` 下不依赖动画表达状态。
