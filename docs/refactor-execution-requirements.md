# V2 重构执行要求（唯一入口）

本文件是 V2 重构的最高优先级执行约束。阶段计划只描述“做什么”，不得覆盖这里的“怎么做”。

## 每阶段强制预检

主代理在每个代码阶段、审计阶段、部署阶段开始前，以及上下文压缩、用户纠正或任务恢复后，必须：

1. 从头到尾重新阅读本文件。
2. 重新阅读主计划中当前阶段、验收标准和下一批任务。
3. 检查 `git status --short --branch`，区分本阶段改动与用户既有改动。
4. 在 commentary 明确本阶段目标、边界和门禁，再开始编辑或委派。
5. 给每个 Terra 子智能体的任务中要求其先阅读本文件和当前阶段计划；未读不得实施。

## 不可漂移的产品与环境边界

- 唯一实施目标是 V2：本地 `Video_analyzer-ui-4004`、分支 `v2`、服务器 `/home/openclaw/Video_analyzer-ui-4004`、Compose 项目 `short-video-analyzer-ui-4004`、端口 4004。
- 4002 正式版和 4003 开发版只允许只读健康检查；不得构建、重启、部署或改写。
- 功能对齐已先于重构完成。后续结构调整必须保持 V2 活动功能、URL、API schema、SSE、数据目录和 UI 行为，除非用户明确批准行为变更。
- 已退役 provider 按“彻底删除”处理：零运行时代码、零路由/别名、零兼容、零测试特判、零配置、零 Skill/MCP、零文件名、零数据目录、零文档历史和零日志探针。不得在后续计划、总结或常规黑盒中继续复述其专名或请求旧 URL；审计历史只保留在 Git 历史。
- 活动聊天 provider 只有 Home、SellerSprite、出海匠；未知外部 provider 统一 fail-closed，不为任何已退役值增加专用分支。

## 实施与同步规则

- 本地不进行 Docker 构建。代码先在 Windows 工作树完成静态检查与专项测试，再提交并通过 GitHub 代理推送；服务器使用代理拉取同一 `v2` 提交。
- 服务器只通过 `bash scripts/deploy_ui_4004.sh` 构建并部署 4004 专属镜像，不使用 SCP/SFTP/rsync 或 SSH 输入传源码。
- 每个提交只做一种性质的工作：行为修复、结构迁移、测试基线或文档收口不得混杂。
- 改动保持最小、按领域命名并显式注入依赖；不得为了减少 `web_app.py` 行数建立通用框架、反向依赖或跨领域抽象。
- 用户已有的修改和未跟踪文件默认保留。若它们命中用户明确要求的全仓零残留门禁，只允许对命中内容做可审计的最小清理，不得覆盖其他内容。

## Terra 协作规则

- 复用现有 Terra 子智能体，按互斥文件所有权拆分审计、实现和交叉复核；避免无限创建任务记录。
- 子智能体不得独立提交或部署。主代理必须复核其 diff、测试有效性、依赖方向和需求边界，再统一提交。
- 高风险集成点至少采用“一人实现、一人交叉审查、主代理终审”；审查意见未收口不得进入服务器门禁。

## 一次性脚本与 TTL

- 一次性迁移、审计、修复、数据检查或调试脚本允许使用，但只能放在 `scripts/temporary/`，并在创建时登记到 `scripts/script_lifecycle.json`。禁止先提交、使用后再补登记。
- 清单必须声明唯一 `active_phase`；每项登记必须包含 phase、owner、用途、创建日期、到期日期、删除条件和转正条件。默认最长 TTL 为 14 天，日期按 UTC 自然日计算；所属阶段验收完成与日期到期取更早者，触发后必须删除或转正并清空/切换 `active_phase`。
- 到期扫描只允许报告失败，不得自动删除。删除必须先确认无生产、Compose、部署、文档或测试调用；涉及数据写入的脚本还要确认没有恢复用途。
- 转正必须证明它是稳定的运行、部署、恢复或用户支持入口，迁出 `scripts/temporary/`，补齐使用说明、安全边界和相应验证，并从 TTL 清单删除。不得仅以“以后可能有用”为理由延期。
- 阶段专项测试默认复用现有测试文件。新增 `test_*.py` 必须证明是独立长期门禁；临时测试不得命名为 `test_*.py`，避免混入自动发现。阶段总结必须分别报告新增、转正和删除的脚本。
- 用户未跟踪脚本属于用户资产，不得擅自登记、移动或删除；只能报告其缺少 TTL 元数据并等待用户自行纳管。

## 每阶段完成门禁

- 先运行本阶段专项、语法检查、`git diff --check`、CodeGraph 依赖审计和零残留扫描。
- 提交、推送、服务器拉取并构建新的 4004 专属镜像后，从镜像实际 `test_*.py` 清单自动发现并运行全部登记的确定性 Python 套件、两个 Node 门禁、独立热报续跑，以及两个桌面/移动 Playwright。
- 当前基线为 54 项确定性回归 + 2 项 Playwright = 56 项；新增专项脚本时同步增加总数。任何失败都必须在当前阶段修复并从头重跑完整集合。
- 部署后检查 14 个现存页面：`/`、`/chat`、`/amazon`、`/chuhaijiang`、`/report`、`/report/player`、`/extract`、`/shop`、`/tool`、`/metrics`、`/lan-chat`、`/proxy`、`/taobao`、`/harness`；同时检查受影响端点黑盒、未知 provider fail-closed、4002/4003/4004 健康、4004 专属镜像、服务器 clean checkout 与近期日志错误。不再对已退役 URL 做专项请求。
- 每阶段结束必须先给出总结，再做需求漂移、模块解耦、复用合理性、安全边界和测试有效性审计，随后修正主计划。审计未通过不得进入下一阶段。

## 仅在高风险时暂停

只有以下情况需要停下来请求用户决定：可能触碰 4002/4003、破坏或迁移真实数据、改变外部 API/鉴权/会话归属、改变 Range/流式/下载安全语义、需要新增外部权限或无法恢复的操作。普通测试失败、局部实现分歧和低风险结构调整由主代理在既定范围内自行收口。
