# 选品决策 Skill

适用于：发现可进入的 TikTok Shop 商品方向，或对指定商品、链接、类目判断机会、风险和进入条件。

## 触发与边界

- 首先确认市场；用户未指定时可默认 US，并在报告中写明。只有市场无法从上下文判断时才追问。
- 只能使用当前暴露的 FastMoss 工具。类目 ID、product_id 必须来自用户输入或本轮真实返回，不能猜测或跨对象复用。
- 这是一条决策链，不是工具数量竞赛。没有足够证据时说明缺口，不用“覆盖等级”代替分析。

## 核心逻辑

1. 先把关键词解析为真实类目和类目层级；上游类目指标不能写成目标三级类目指标。
2. 在同一市场、同一可比统计周期内看市场规模/增长/集中度、热销样本和新品样本。
3. 从真实商品指标中选出 2–3 个候选，再围绕这些实际 product_id 深挖；候选与深挖对象必须一致。
4. 推荐、观察、淘汰都要给出可核对的指标与条件；已下架或不在售商品不能列为推荐候选。

## 工具与参数

- `search_category_by_words`：以用户关键词解析类目，优先拿到明确的 L3 ID 与名称。
- `market_category_analysis`、`market_category_ranking`：在已确认类目和市场下读取规模、增长、集中度或榜单结构。
- `product_rank_top_selling`、`product_rank_new_listed`：同市场、同类目、同排序口径获取热销与新品样本；可并行。
- `product_search`：仅作补充搜索，不能把关键词命中总数当成市场容量。
- `product_detail_info`、`product_overview`、`product_sales_trend`、`product_investment`、`product_creator_analysis`、`product_video_list`：仅对已入选候选的真实 product_id 调用；参数中的时间范围与报告口径保持一致。

## 并行与推进

1. 类目解析完成后，可并行调用市场分析、热销榜和新品榜。
2. 根据价格、周期销量/GMV、增长、上架状态和实际返回数量筛出 2–3 个候选；不要对榜单全部商品深挖。
3. 对候选并行补充趋势、overview、视频/达人和投放证据。某个接口空或失败时保留其他可用证据，不重复相同调用。
4. 证据已足以区分推荐/观察/淘汰时停止调用，进入最终报告。

## 结果解读与风险

- `price_display`、`floor_price`、`ceiling_price`、`commission_rate_percent`、销量、GMV、首 3 日指标、增长、上下架、跨境/全托管字段均按接口原值保留；不要静默省略或改口径。
- 达人、视频、投放是观察到的关联或领先信号，除非接口直接给出因果证据，不能写成唯一增长原因。
- 不能混合不同市场或币种的 GMV；工具返回的总数不是未返回明细的替代品。

## 最终输出

按实际证据自由组织 Markdown，至少包含：

- 结论：推荐、观察、淘汰及其进入条件。
- 候选对比：产品形态、价格带、销量/GMV/增长、上架状态及可比范围。
- 内容与渠道：可观察到的视频、达人、投放或缺失情况。
- 风险与数据缺口：哪些字段未获取、哪些比较不可直接成立。
- 下一步：可执行的验证、选品或运营动作；不要只写“继续验证”。
