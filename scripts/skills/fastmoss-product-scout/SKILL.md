# FastMoss 选品决策 Skill（本地）

## 适用范围与目标

用于 TikTok Shop 商品选品：在用户给出的市场、类目、关键词或真实商品线索内，依据 FastMoss MCP 已返回的数据判断「推荐、观察或淘汰」以及下一步验证动作。它不是供应链、利润或全网市场研究 Skill。

若用户未指定市场，默认 `US`。运行时日期由系统消息给出；不得请求未来周期。所有比较必须保持同一市场、币种、类目层级和时间口径。事实只能来自本轮 FastMoss MCP 证据；没有证据时明确说明未知。

## 输入与默认值

- 可接受关键词、类目名称/L3 ID、商品 ID、商品链接或自然语言需求。
- 先将自然语言类目解析为 FastMoss 返回的真实类目路径和 ID；不要把上级类目数据称为目标三级类目数据。
- 商品 ID、类目 ID 和候选名称必须来自工具返回或用户直接提供。链接只在用户明确要链接时处理，不作为默认选品步骤。

## 决策步骤

1. 先确定市场、查询周期与真实类目。类目不清楚时先查类目，不猜测 L3 ID。
2. 在同一市场和周期内收集市场/类目信号，以及热销和新品样本；能并行时并行。工具参数优先限制返回量，避免拿到无关的大表。
3. 仅从真实返回商品中选出 2–3 个候选深挖。候选选择应兼顾销量或 GMV、增长或首发表现、价格/佣金和可观察到的内容或投放信号，而不是只看单一排名。
4. 只对入选候选的真实 `product_id` 查询趋势、overview、视频、达人和投放等可用维度。工具结果已经足以支持判断时停止，不按固定调用数继续补工具。
5. 发现空数据、市场/币种/周期冲突、下架状态或实体无法对应时保留该限制；下架商品不得作为推荐候选。

## 工具边界与依赖

本 Skill 只使用当前预设暴露的 FastMoss 工具。工具 schema 暴露和实际执行均由服务端白名单控制；不要建议、尝试或编造未暴露工具。

- 类目解析后才能进行类目口径的市场、热销和新品比较。
- 趋势、overview、视频、达人和投放深挖必须绑定已返回的真实商品 ID。
- FastMoss 返回的价格、佣金、销量、GMV、增速、首日/前三日表现、上下架状态、跨境或托管字段应保留原值和周期；没有该字段时写明未返回，不能填「—」后继续推断。

## 证据解释与表达

每次工具结果会先被压缩为带来源、参数、市场、实体、周期、指标、记录和限制的语义证据。后续分析仅使用这些证据，不复述内部工具名、原始 JSON、缓存审计字段或整张原始表。

对每个重点候选，至少结合两个独立维度的证据再给出推荐或淘汰理由；若只有一个维度，只能写为待验证观察。销量、GMV、增速、价格、佣金、内容和投放信号描述的是 FastMoss 返回范围内的表现，不能自动推出利润、竞争强度、生命周期因果或可复制性。

## 最终回答

先给出是否值得进入下一步的结论，再给出候选对比和推荐/观察/淘汰。逐项解释可见指标意味着什么，给出具体产品形态、价格带、进入条件和下一步验证动作；同时单列风险、证据缺口和不能支持的结论。

不要把数据表当成结论，也不要只回答「继续验证」。在证据不足或调用失败时，展示已取得的关键数据并说明为什么尚不能推荐。

## 明确不支持的结论

FastMoss 没有返回时，供应商成本、MOQ、利润/ROI、物流、认证、1688/Amazon 数据、全球市场规模、季节性因果均为未知。不得编造，也不得将用户的主观假设包装为事实。
