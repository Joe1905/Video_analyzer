# 市场可行性复核

## 判断对象与边界

回答“以当前证据和约束，这个方向是否值得投入下一步工作”。先识别具体候选、人群、地域、场景、当前阶段及拟开展的下一步。判断仅适用于这个对象和投入层级：值得继续研究不等于值得开发，值得打样不等于值得备货。对象不清时先从记录恢复，只有实质影响判断且无法推断的条件才问用户。

本模块可被不同阶段重复读取和使用，不依赖 SociaVault 或某个发现 Skill。研究模块负责探索、取证和执行切换；本模块负责判断及指出最影响决策的缺口。可利用适用工具核验决定性的疑点，但不要自行包办完整市场调查、供应商筛选或经营执行。

## 按阶段和证据判断

从现有研究和证据开始，选择能改变当前决定的因素。需求是否真实且有足够影响，用户是否采取行动或付费，已有方案是否留下可进入的缺口，以及触达、价格、成本或实施约束是否使机会不成立，都是可能的判断依据，不是每次必填的目录。竞争多不自动淘汰，竞争少也不自动通过；关注具体人群和可实现的差异。

发现阶段允许以真实问题、替代行为和方案缺口支持继续调查，无需提前知道完整成本。到了产品或商业投入阶段，应以拟投入工作的风险决定证据要求：例如涉及利润时核实价格、成本口径和关键假设，不能沿用早期的需求信号作为盈利证明。不要因本阶段尚不需要的数据缺失淘汰方向，也不要因发现阶段已通过而跳过后续复核。

区分来源事实、推断和未知，检查地域、日期、统计口径、来源独立性及反证。热度、口头喜欢、询价不等于成交；假设演算不构成真实收益证据。工具故障或证据覆盖不足不等于没有市场。需要补证时指出最可能改变决定的问题，取证方法交给研究模块自主选择，不生成必须遍历的完整清单。

## 给出可执行的判断

用于多市场日报时，分别评判每个市场，不能以某个方向成立替代其他方向的判断。当前 v1 的下一步是运营跟进研究，明确区分“值得验证”与“可以投入经营”。为调用方提供可比较的理由、关键阻碍及下一项最有价值的验证；不要仅凭热度或不一致的销量口径给跨市场排名，也不要为了日报必须推荐而降低证据要求。

根据证据给出明确的下一步建议，可以继续、带条件继续、补证、调整、暂缓或淘汰；用语和形式随任务，不设固定评分与通用门槛。

- 足以支持下一步时，说清支持的具体投入及成立条件，不笼统宣布“市场可行”。
- 关键事实有反证、已有方案足够或硬约束使当前机会不成立时，说明淘汰的对象及原因。某产品失败不自动否定整个品类，某地域不成立也不外推所有市场。
- 关键未知且短期难以查清，或继续取证价值低时，可以建议暂缓并切换；说明这是当前投入判断，不是不存在需求的事实结论。
- 可通过收窄人群、改变方案或补一项关键证据改善判断时，给出理由；不要为了保留原方向不断改写假设。

调用方依据建议决定继续、换细分或换品类，并遵守用户范围与资源边界。本模块不自动扩大任务、执行采购或启动后台任务。

## 持续复核与落盘

在准备进入下一阶段、增加实质投入、出现重要支持或反对证据、范围或关键约束改变、旧证据时效不再适用时复核。没有相关变化就复用仍适用的判断，不在每次工具调用后重复全量审查。后续证据可以推翻前期判断；只修订受影响的候选和依赖该判断的分支，不机械重跑全部研究。

沿用调用方的研究目录和证据标识。默认在 `feasibility.md` 维护各候选的当前判断及重要修订，已有等效文件则沿用；在 `research.md` 的对应分支链接该判断。独立使用且没有目录时，在可写工作区建立独立研究目录并告知位置，不写入 Skill 安装目录。

记录应让下一次调用看懂：候选标识及范围、当前阶段与拟投入工作、判断日期、支持与反对证据引用、关键未知、建议与成立条件，以及何种变化需要复核或重开。首次判断后新增重要变化及原因，保留旧结论的适用范围，不覆盖原始事实。没有证据文件时把实际取得的重要材料一并保存，不能只留空引用。

改变判断时同步研究记录中的状态，注明被替代或需要复核的相关结论；无法修改调用方文件时明确返回待同步事项，不能声称已同步。写入失败则说明未持久保存。交付围绕当前决定展开，不强制表格、篇幅、候选数量或 JSON 结构。
